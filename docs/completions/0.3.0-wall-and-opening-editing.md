# 0.3.0 — Walls mode: hand-correct the trace, place doors/windows/entrances

**Date:** 2026-08-03
**Goal:** When the digitiser gets a floorplan 90 % right, the last 10 % must be a minute's work, not a re-upload. This adds a second editing mode to the plan — **Walls** — where the boundary itself and its openings are directly editable: drag corners, push whole walls in/out, add/remove corners, and place doors, double doors, windows and entrances with a click. This is the 0.0.2 direction ("the correction UI *is* the editor") made real.

**Status: built, build- and lint-clean, and verified live** — scripted headless-Chrome runs drag corners, push walls, insert/remove corners, place/drag/resize openings and assert the derived stats and the 3D view follow. Deployed target: same Vercel app (redeploy manual, `pnpm build && vercel deploy --prod` from `app/`).

---

## Why this shape

- **One mode toggle, not a second tool.** The plan canvas gets a `Layout | Walls` segmented control (top-left, same pattern as the walkthrough's Orbit/Walk). Layout is exactly the old editor; Walls turns the *shell* interactive and fades the furniture to spectators. Everything else — pan, zoom, fit, the scale pill — is shared. The user corrects the trace in the same place they plan, on the same store.
- **Openings are anchored by centre point, not edge index.** The domain stores `Opening.edge + offset`, but every boundary mutation re-homes each opening by projecting its centre onto the *new* boundary (`reprojectOpenings`). That single decision makes all boundary edits composable: move a corner, split an edge, push a wall — the door stays where the door is, offsets and edge indices are recomputed, and anything stranded > 2 m from a wall is dropped rather than guessed. It is the same centre-point philosophy the digitiser already uses for model output ("the model never invents edge indices" — now the editor doesn't either).
- **Dimensions always visible while editing.** In Walls mode every wall shows its live length just outside the boundary (rotated along the wall, `fmtLength`). Spotting "the model traced this wall 200 mm short" requires seeing the number; fixing it is a drag (25 mm snap) or typing the true length in the Inspector.
- **Perpendicular wall push is the headline gesture.** Grabbing a wall and sliding it in/out along its normal (both corners move together, snapped) is how you correct the most common trace error — a wall in slightly the wrong place — in one motion. Openings on that wall keep their offsets and ride along, courtesy of the reprojection.
- **`entrance` becomes a first-class opening kind.** Shopfront/lobby entries with no door leaf were previously forced into "double-door". Plan symbol: open gap with a dashed threshold. 3D: same lintel treatment as doors (the existing `buildWallBoxes` already treats every non-window as a door-height opening, so the walkthrough needed **zero changes**). The digitiser's trace schema now offers the same enum value, so uploads can classify entrances too.

## What changed, file by file

### `app/src/features/scheme/types.ts`
- `OpeningKind` gains `"entrance"`. Nothing else — the domain model already had everything the editor needs.

### `app/src/features/plan/planGeometry.ts` (shared geometry — 2D, 3D and digitiser all consume this)
- `projectPointToBoundary(boundary, x, y)` — nearest point on any edge, returning `{edge, t, dist, len, x, y}`. Now the single projection primitive for the store, the canvas ghost preview *and* the digitiser.
- `clampOpeningToEdge(offset, width, edgeLen)` + `MIN_OPENING_WIDTH` (300 mm) — spans can never leave their edge or collapse.
- `reprojectOpenings(oldBoundary, newBoundary, openings, tolerance = 2000)` — centre-point re-homing described above (computes each centre with `placeOpening` on the old boundary, projects onto the new).
- `DEFAULT_OPENING_WIDTHS` (door 900 / double 1800 / window 1800 / entrance 2400) and `OPENING_KIND_LABELS` — one source for toolbar, inspector and labels.

### `app/src/features/scheme/store.ts`
- New UI state: `planMode: "layout" | "walls"` and `wallSelection` (`vertex | edge | opening | null`), mutually exclusive with item/room selection; cleared by `resetDemo`/`loadScheme`/mode switch.
- Boundary actions — all funnel through one `withBoundary` helper that rejects degenerate polygons (< 3 corners, any edge < 50 mm) and reprojects openings:
  - `updateBoundaryVertex(i, x, y)` — corner drag / numeric X-Y.
  - `insertBoundaryVertex(edge, x, y)` — midpoint "+" handles and "Split into two walls"; returns the new index (or −1 if rejected) so the canvas can hand the fresh corner straight to the drag.
  - `removeBoundaryVertex(i)` — guarded at 3 corners.
  - `setEdgePosition(edge, a, b)` — both endpoints at once; the canvas computes the snapped perpendicular delta from the drag-start positions so repeated move events never compound.
  - `setEdgeLength(edge, mm)` — re-lengths along the wall's direction; the far corner moves. Used by the Inspector's length fields.
- Opening actions: `addOpening(kind, x, y)` (projects the click, ≤ 1.5 m tolerance, default width clamped, selects the result), `updateOpening` (kind/width/offset, clamped), `moveOpeningTo` (drag re-homing, may cross to another wall), `resizeOpeningTo(id, "start"|"end", x, y)` (end-handle drag along the opening's own edge, far end pinned), `removeOpening`.

### `app/src/features/plan/PlanCanvas.tsx`
- **Toolbar overlay** (top-left): `Layout | Walls` Segmented; in Walls an "Add" group (Door / Double door / Window / Entrance) where the armed tool is accent-filled (consistent with Segmented-selected semantics), plus a hint pill ("Click a wall to place · Esc to cancel" / drag hints).
- **Walls layer** (rendered only in Walls mode, above the faded items):
  - per-edge invisible fat hit-lines (`WALL_T + 280`) — click selects the wall, drag slides it along its outward normal; selected wall gets an accent overlay;
  - live dimension labels outside each wall, flipped to stay upright (note: `placeOpening`'s `(nx, ny)` actually points *outward* for the store's clockwise y-down winding — its old comment says otherwise — both new label offsets rely on the empirically verified direction);
  - opening hit-rects above the walls: click selects, drag moves **with the grab offset preserved** (no jump-to-cursor), selected openings get an accent outline, two square end-handles for width resize, and a floating "Door · 900 mm"-style label;
  - midpoint "+" handles on every edge ≥ 900 mm: pointer-down inserts a corner *and* immediately starts dragging it — add-and-place is one gesture;
  - corner circles: drag with 25 mm snap;
  - ghost preview while a tool is armed: translucent accent span projected onto the nearest wall under the cursor (≤ 1.5 m), exactly where the click will land it;
  - a full-canvas crosshair overlay while armed so the placement click can't fall through to pan/deselect.
- **Keyboard** in Walls mode: Delete/Backspace removes the selected corner or opening, arrows nudge (corner in x/y, opening along its wall; Shift = 100 mm), Esc disarms the tool then clears selection. Layout-mode keys unchanged.
- Drag plumbing: the old `dragRef` union grew `vertex`/`edge`/`opening`/`opening-resize` variants; a single `beginDrag` callback does pointer-capture + ref assignment (also keeps the React compiler's `react-hooks/refs` rule happy — inline `dragRef.current =` writes inside the openings map were flagged).
- New `entrance` plan symbol: wall gap + dashed threshold line.

### `app/src/features/plan/Inspector.tsx`
- Branches on `planMode`; Walls mode renders one of four panels:
  - **Corner** — X/Y in mm, plus "From previous corner" / "To next corner" lengths (editing one slides the far corner along the wall — the numeric way to fix a mis-measured wall), Remove corner (disabled at 3).
  - **Wall** — length (editable), openings-on-this-wall count, "Split into two walls".
  - **Opening** — kind select (all four), width + from-corner in mm, host wall info, delete.
  - **Nothing selected** — how-to text + the unit summary card (now also shows corner count).
- All Walls numeric fields use a new `CommitField` (commit on blur/Enter, uncontrolled with `key={value}` resync) because boundary edits clamp and snap — live per-keystroke writes would fight the user mid-typing. The Layout item fields keep their original live behaviour.
- The unit summary card was extracted to `UnitSummary` and reused by both empty states.

### `app/src/features/ingest/digitise.ts`
- `projectOpening` now delegates to the shared `projectPointToBoundary` + `MIN_OPENING_WIDTH` (behaviour identical, tolerance still 1.2 m) — the duplicated projection loop is gone.

### `app/src/app/api/digitise/route.ts`
- Trace schema `kind` enum gains `"entrance"` with a one-line description ("open shopfront/lobby entry with no door leaf drawn").

## Deliberate scope edges

- **No undo stack** — edits are individually reversible by dragging back / retyping, and nothing here made the missing undo worse; it remains the obvious next infrastructure piece if editing deepens.
- **No self-intersection guard** — you can drag a corner across the far wall and make a bow-tie; "always editable, never a black box" cuts both ways, and the area/3D make the mistake immediately visible. The guard only rejects degenerate (< 50 mm) edges.
- **Scale provenance untouched by hand edits** — moving a corner operates *within* the established px→mm scale; it changes geometry, not how scale was obtained, so the sidebar's provenance line stays honest.
- **Columns not editable** — the ask was outer walls + openings; columns still come from the digitiser only.
- Unchanged gaps: no persistence, welcome dialog reopens each load, "Share scheme" UI-only.
