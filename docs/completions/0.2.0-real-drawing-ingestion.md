# 0.2.0 — Real drawing ingestion: upload → Claude vision digitiser

**Date:** 2026-07-31
**Goal:** Complete the functional integration so a user can upload a PDF (or image) of a floorplan and the platform actually traces it — replacing the scripted stub that played a 4-step animation and always returned the demo unit.

**Status: built and build-verified; live end-to-end run pending an `ANTHROPIC_API_KEY` in `app/.env.local`.** Everything below compiles clean (`pnpm build`, TypeScript included) and lint shows only the 4 documented pre-existing `WalkthroughView.tsx` errors. A purpose-built test lease plan is ready for the live verification pass.

## Why this shape

The previous "digitiser" discarded the file entirely — `onDrop` never touched `e.dataTransfer`, the file input's `onChange` ignored its event, and a 900 ms-per-step timer played hardcoded narration describing the demo unit. The product vision (docs/openspace.md) and the 0.0.2 direction entry both frame ingestion as an *agentic measurement loop* with honest provenance. This implementation makes the four steps the dialog already showed — read, scale, trace, check — real:

- **Two vision passes on `claude-opus-5`**, not one: pass 1 reads the drawing and establishes scale (with the ranked ladder from 0.0.2: printed dimension strings → scale bar → stated area → object priors, each mapping to a `Provenance` of `measured`/`derived`/`inferred`); pass 2 traces geometry in real-world mm *using* pass 1's scale findings. Two passes give the dialog a real progress beat and keep each structured output small and reliable.
- **The check step is computed in code, not asked of the model.** Shoelace area of the traced boundary vs the stated area from the title block; >15 % deviation downgrades the scale confidence shown in the sidebar. "Honest about scale" means the self-check can't be hallucinated.
- **The model never invents edge indices.** `Opening.edge`/`offset` is the trickiest part of the domain model for an LLM to emit directly; instead the model reports openings and columns as centre coordinates + width, and we project them onto the nearest boundary edge geometrically. Openings that land >1.2 m from any wall are dropped (and counted), not guessed.
- **PDFs go to Claude natively** as base64 document blocks (32 MB / native PDF support on the API) — no pdf.js, no server-side rasterisation. Images (PNG/JPG/WebP/GIF) go as image blocks.

## What changed, file by file

### New — `app/src/app/api/digitise/route.ts`

Next 16 route handler (`POST`, node runtime, `maxDuration 300`). Accepts multipart form data, validates type/size (≤ 20 MB), and streams back **newline-delimited `DigitiseEvent` JSON**: `step` events (`read`/`scale`/`trace`/`check` × `active`/`done` with real detail strings) followed by a `result` carrying a complete `Scheme`, or an `error`. Uses `@anthropic-ai/sdk` (new dependency, v0.115.0) with:

- `client.messages.stream()` + `finalMessage()` (streaming per SDK guidance for long outputs; `max_tokens` 32 000 — on Opus 5, thinking is on by default and counts against the cap),
- **structured outputs** (`output_config.format` with strict JSON schemas) for both passes — no prompt-and-pray JSON parsing,
- explicit handling for `refusal` and `max_tokens` stop reasons, and typed SDK errors mapped to actionable messages (bad key, rate limit).

The final `Scheme` is fresh: the traced `Unit`, empty `rooms`/`items`/`references` — you start planning from your own drawing, the demo stays reachable via "Explore the demo unit" / Reset.

### New — `app/src/features/ingest/digitise.ts`

The shared contract between route and dialog, plus pure normalisation (usable and testable without the API):

- `DigitiseEvent` / `ReadFindings` / `TraceFindings` types,
- `normaliseUnit()` — snap to the 25 mm grid (`planGeometry.snap`), drop collapsed vertices, translate to origin, **enforce clockwise winding** (screen-coords shoelace sign — what the SVG plan and 3D extrusion both assume), project openings/columns onto edges, clamp column sizes, default ceiling to 3 000 mm when unstated,
- `areaCheck()` — the computed self-check with its user-facing detail string.

### Rewritten — `app/src/features/ingest/WelcomeDialog.tsx`

- Drop and file-picker paths now **send the actual file** (`FormData` → `/api/digitise`) and stream the response with a `ReadableStream` reader.
- The 4-step list is driven by real events: `todo → active (spinner) → done (tick + detail)` per step, details straight from the digitiser (e.g. what pass 1 found, corner/opening/column counts, the area check verdict).
- Proper error state: warning panel with the actual message + "Try another file" / "Explore the demo unit" exits. Client-side type validation for fast feedback on wrong files.
- In-flight runs abort (`AbortController`) on Esc, backdrop click, close button, or unmount.
- On `result`: `loadScheme()` into the store, then the dialog closes after a beat so the last tick lands — the workspace behind it is already showing the traced unit.
- Footer no longer claims the digitiser is a stub.

### Edited — `app/src/features/scheme/store.ts`

New `loadScheme(scheme)` action — replaces the whole scheme and clears selections. Because all four views + StatsBar derive from this one store, the traced unit is immediately the plan, the walkthrough geometry, and the (empty) cost base with no further wiring.
